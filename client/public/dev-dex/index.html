🛑 Emergency Stop & Recall — new in the 2.0 contracts

Older pool contracts had no brake: when a key was compromised, pools could be drained and nothing could stop it. The new contract design is built with a recall switch held by the owner alone:

  • One tap pauses trading on the pool.
  • Funds held inside the contracts sweep to a pre-set safe wallet — the money sitting in the pools is pulled out of harm's way.
  • Recall windows on dangerous changes — migrations and admin changes wait 24 hours (standard) or 7 days (critical) before they can run, with alerts when one is scheduled and again before the window closes — a stolen key can't finish a drain in silence.
Contract-held funds only — never a settled wallet balance.

🛡️ How Dev Shield decides

Shield is an automated security engine — a fixed set of on-chain checks that run in your browser before a trade can be signed. It is not a person and it does not guess: every line in its verdict comes from a check that just ran against the live chain.

  • Pool code & admin — the pair contract's code and admin must match the verified record. Any change = the pool is blocked. (The October drains began with contract code changes.)
  • Token admin & minter — whether the token's admin can still change its contract, and whether new tokens can still be minted. Shown plainly, either way.
  • Sell test — the pool is asked to price a sale of the token you would receive, before you buy. If the sell side fails, the trade is blocked.
  • Price impact — how much your own trade moves the price. Big moves are flagged loudly.
  • Your permissions — when your wallet is connected, Shield lists permissions (authz grants) your wallet has given away. A grant with no expiry is flagged red.

What Shield cannot do: it cannot undo or reverse a trade that has already settled on-chain — no tool can, on any non-custodial pool. If a pool ever trips the wire, the response is to alert the operator, banner the pool here, and trace any moved funds to the exchanges. That is why the checks run before you sign.

🔧 How a repair works

When something goes wrong, this is the playbook — in order:

  • ① Detect — Dev Shield and the operator monitor watch every pool around the clock. If a pool's contract code or admin changes, or an attack pattern appears, the alarm fires straight away.
  • ② Pause — one tap of ⏸ Pause Trading freezes swaps on the pool. The funds stay where they are; trading just stops while things get checked.
  • ③ Recall — if the threat is real, 🛑 Emergency Recall sweeps the funds held inside the contracts to the pre-set safe wallet, out of harm's way, and the pool shuts down.
  • ④ Fix — with the funds safe, the problem gets repaired: contract code or admin restored, keys rotated. And if anyone has scheduled a dangerous change, it is still sitting in its recall window, where ↩️ Cancel Pending Action kills it before it can ever run.
  • ⑤ Resume — trading restarts only when the pool verifies against the chain record again. If it does not verify, it stays closed.

On the current contracts there is no playbook — no pause, no recall, nothing to press. That is the gap the new contract design closes.

🔑 Who can press them

  • The owner alone. Only the contract owner's wallet can pause, recall, or cancel. Nobody else — not this website, not a server, not a bot.
  • Multi-sig where feasible — the owner can be a multi-sig wallet, so no single person and no single key can act alone.
  • One tap of the owner's, from their own wallet — every action is signed by the owner in their own wallet app. No server ever holds keys, and nothing anywhere can press these controls for them.
  • Alerts fire both times it matters — when a dangerous action is scheduled, and again before its recall window closes, the owners are pinged. A stolen key cannot finish a dangerous change in silence.

🛡️ Dev Shield — checked before every trade

Shield is an automated security engine — a fixed set of on-chain checks that run in your browser before a trade can be signed. It is not a person and it does not guess: every line in its verdict comes from a check that just ran against the live chain.

  • Pool code & admin — the pair contract's code and admin must match the verified record. Any change = the pool is blocked automatically. (The October drains began with contract code changes.)
  • Token admin — whether the token's admin can still change its contract. An admin renounced to the burn address means nobody can change it — the safer state — and Shield shows the state plainly, either way.
  • Token minter — whether new tokens can still be minted, and who holds that power.
  • Sell test — before you buy, the pool is asked to price a sale of the token you would receive. If the sell side fails, the trade is blocked — a token you cannot sell back never gets your signature.
  • Price impact — how much your own trade moves the price. Over 5% is flagged; over 15% is flagged red.
  • Your permissions — when your wallet is connected, Shield lists the permissions (authz grants) your wallet has given away. A grant with no expiry is flagged red — the kind of open door the October attack walked through. The full wallet check lives in the Wallet security watch, right under the header.

What Shield does not check — stated plainly: it cannot undo or reverse a trade that has already settled on-chain (no tool can, on any non-custodial pool), and it does not judge a token's team, promises, or off-chain claims — it reads contracts, not reputations. If a pool ever trips the wire, the response is to alert the operator, banner the pool here, and trace any moved funds to the exchanges.
